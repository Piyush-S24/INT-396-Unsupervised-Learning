1Support, confidence, lift and conviction

Four numbers describing one rule. Reading only the first two is how people act on rules that are worthless.

All four
supp = count(A∪B)N,  conf = supp(A∪B)supp(A),  lift = confsupp(B),  conv = 1 − supp(B)1 − conf
Lift and conviction both compare the rule against chance. Confidence does not, which is exactly why it misleads.
Why some books write supp(A ∩ B) instead
Both are right — they describe different objects. Here A and B are itemsets, so the rule covers baskets holding every item of A and every item of B — the itemset A ∪ B. Write A and B instead for the events “this basket contains A”, equivalently the transaction sets T(A) and T(B), and the same baskets are the intersection T(A) ∩ T(B), giving P(A ∩ B). Adding items can only shrink the matching baskets — the same fact the Apriori principle rests on — so union on itemsets equals intersection on transactions: supp(A ∪ B) = P(A ∩ B). In the example below both give 3/7 for {Jam} → {Butter}. What is genuinely wrong is applying ∩ to the itemsets: {Jam} ∩ {Butter} = ∅, whose support is 1.
The method — what to actually do
  1. Count N, the total number of baskets.
  2. Count baskets containing A, containing B, and containing both.
  3. supp(A∪B) = both / N.
  4. conf = both / count(A) — divide by a count, not by N.
  5. lift = conf / supp(B). Compute supp(B) on its own first.
  6. conv = (1 − supp(B)) / (1 − conf). If conf = 1 the denominator is 0 and conviction is ∞.
  7. Judge on lift, and report confidence alongside it, never alone.
Worked example — three rules, and the trap
Seven baskets: {E,J} {B,J,M,U} {E,U} {E,M,U} {B,J,M,U} {B,J,U} {J,M}. B = Bread, J = Jam, U = Butter, M = Milk, E = Eggs. Counts: B 3, J 5, U 5, M 4, E 3; {J,U} 3; {B,J,U} 3.
  1. Rule 1 {Bread} → {Jam, Butter} — support37 = 0.4286
  2. Its confidence33 = 1.0000
  3. Its liftsupp({J,U}) = 37 = 0.4286 → lift = 1.00000.4286 = 2.333
  4. Its conviction1 − 0.42861 − 1.0000 = 0.57140 = ∞ — the rule never once fails
  5. Rule 2 {Jam} → {Butter}conf = 35 = 0.600; supp(U) = 57 = 0.714 → lift = 0.6000.714 = 0.840
  6. Its conviction1 − 5/71 − 3/5 = 2/72/5 = 57 = 0.714 — also below 1
  7. Rule 3 {Jam} → {Bread} — same confidenceconf = 35 = 0.600; supp(B) = 37 = 0.4286 → lift = 0.6000.4286 = 1.400
Rules 2 and 3 have identical confidence (0.600) and opposite verdicts. Butter is in 5 of 7 baskets anyway, so Jam makes it less likely; Bread is in only 3, so Jam genuinely predicts it. Sort an association table by confidence and you will act on rule 2.
Practice
  1. From 2000 baskets: Nappies 300, Beer 400, both 150. Compute all four measures for {Nappies} → {Beer}.
    supp = 150/2000 = 0.075. conf = 150/300 = 0.50. supp(Beer) = 400/2000 = 0.20 → lift = 0.50/0.20 = 2.5. conv = (1−0.20)/(1−0.50) = 0.80/0.50 = 1.6. Strong positive association.
  2. A rule has lift exactly 1.0. What does that mean, whatever its confidence?
    A and B are statistically independent — knowing A tells you nothing at all about B. A confidence of 0.9 with lift 1.0 simply means B appears in 90% of all baskets. The rule is worthless.
  3. Why is conviction ∞ when confidence is 1?
    The denominator is 1 − conf = 0. Conviction measures how often the rule would be wrong by chance divided by how often it is wrong; if it is never wrong, that ratio is unbounded. Report it as ∞ and note the rule has no counterexample in this data.

2Apriori and FP-Growth

With d items there are 2d possible itemsets. Both algorithms exist to avoid counting them all.

The Apriori principle
A ⊆ B  ⇒  supp(A) ≥ supp(B)  ⇒  A infrequent ⇒ every superset infrequent
Downward closure. Adding an item can only reduce support, so one failed count eliminates an entire branch without ever being examined.
The method — what to actually do
  1. Level 1: count every single item. Keep those with count ≥ minsup.
  2. Join: combine surviving k-itemsets in pairs to form candidate (k+1)-itemsets.
  3. Prune: discard any candidate having an infrequent k-subset — this is where the saving happens.
  4. Count the survivors with one database pass. Repeat until nothing survives.
  5. Apriori needs one pass per level and generates candidates.
  6. FP-Growth: pass 1 counts items; sort them by descending frequency.
  7. Pass 2 inserts each basket, rewritten in that order, into a prefix tree, reusing shared prefixes. Two passes total, zero candidates.
Worked example — Apriori level by level, then the FP-tree
The same seven baskets, minimum support 3 of 7.
  1. Level 1 countsJ = 5, U = 5, M = 4, B = 3, E = 3 → all five survive
  2. Join to level 25 × 42 = 10 candidate pairs
  3. Count them{J,U} 3, {J,M} 3, {J,B} 3, {U,M} 3, {U,B} 3, {M,B} 2, {E,U} 2, {E,M} 1, {E,J} 1, {E,B} 0
  4. Prune{M,B}, {E,U}, {E,M}, {E,J}, {E,B} all fall below 3 and are dropped
  5. Apply downward closurebecause {E,J} is infrequent, every superset — {E,J,U}, {E,J,M}, {E,J,B}, {E,J,M,U}… — is infrequent and is never counted
  6. Level 3: only sets whose every pair survived{J,U,B} qualifies ({J,U}, {J,B}, {U,B} all frequent) → count = 3 ✓
  7. Total Apriori work17 candidates counted over 3 database passes
  8. Now FP-Growth. Order items by descending countJ(5) → U(5) → M(4) → B(3) → E(3), ties alphabetical
  9. Rewrite each basket in that order and insert{B,J,M,U} → JUMB, which appears twice — the second insertion creates no new nodes, it just increments four counters
  10. Tree size11 nodes represent all 7 baskets, in 2 passes, with 0 candidates
Largest frequent itemset {Bread, Jam, Butter} at 3/7. Apriori: 17 candidates, 3 passes. FP-Growth: 0 candidates, 2 passes. The saving comes entirely from the frequency ordering — insert alphabetically and the tree stops compressing.
Practice
  1. Items A, B, C, D are all frequent. How many level-2 candidates does the join produce?
    4 × 32 = 6: AB, AC, AD, BC, BD, CD.
  2. {A,B} is infrequent. Which level-3 candidates can be skipped without counting?
    Every superset of {A,B}: {A,B,C}, {A,B,D} and any larger set containing both A and B. By downward closure they cannot possibly reach minimum support, so no database pass is needed for them.
  3. Why must FP-Growth sort items by descending frequency before insertion?
    So the most common items sit nearest the root and the maximum number of baskets share a prefix. Insert in any other order and the tree becomes wide and shallow with almost no sharing — you pay the memory cost of the tree and get none of the compression.

3Local Outlier Factor

Three quantities computed in order. Each depends on the one before, so the bookkeeping matters as much as the formulas.

Steps 1 and 2
reachk(A, B) = max [k-dist(B),  d(A, B)],   lrd(A) = 1mean reach to A's k NN
The floor stops a very close pair producing an explosively large density. Note reach is not symmetric.
Step 3
LOF(A) = mean lrd of A's k neighbourslrd(A)
≈ 1 means as dense as the neighbourhood — normal. > 1 means the neighbours are denser than you are — outlier.
The method — what to actually do
  1. For every point, find its k nearest neighbours and its k-distance (the distance to the k-th).
  2. For each point A and each of its neighbours B: reach = max(k-dist(B), d(A, B)).
  3. lrd(A) = 1 / (mean of those reach values).
  4. LOF(A) = (mean lrd of A's neighbours) / lrd(A).
  5. Read the result: ≈ 1 normal, ≫ 1 outlier. There is no absolute distance threshold anywhere — that is what makes it local.
  6. Keep 4 decimals; the ratios are small and rounding early destroys them.
Worked example — LOF for five points, computed in full
A(1.0, 1.0) B(1.2, 1.4) C(0.8, 1.3) D(1.4, 1.0) in a tight cluster, plus O(4.0, 4.0) alone. Take k = 2.
  1. k-distances (distance to the 2nd nearest)A: 0.4000, B: 0.4472, C: 0.4123, D: 0.4472, O: 3.9699
  2. Nearest-neighbour setsA: {C, D}; B: {C, A}; C: {A, B}; D: {A, B}; O: {B, D}
  3. Local reachability densitieslrd(A) = 2.3269, lrd(B) = 2.3269, lrd(C) = 2.3607, lrd(D) = 2.3607
  4. And for Oits reach distances are around 3.9 → lrd(O) = 0.2567, an order of magnitude lower
  5. LOF(A) = mean lrd of {C, D} divided by lrd(A)(2.3607 + 2.3607) / 22.3269 = 2.36072.3269 = 1.0145
  6. The rest of the clusterLOF(B) = 1.0073, LOF(C) = 0.9857, LOF(D) = 0.9857
  7. LOF(O) = mean lrd of {B, D} divided by lrd(O)(2.3269 + 2.3607) / 20.2567 = 2.34380.2567 = 9.1300
The cluster sits at ≈ 1.0; O scores 9.13. O's neighbours are about nine times denser than O is. The threshold is set just above 1, not at any absolute distance — which is exactly what lets LOF work when one region of the data is naturally sparser than another.
Practice
  1. A point has LOF = 1.05. Outlier or not?
    Not an outlier. 1.05 means its neighbours are only 5% denser than it is, which is ordinary variation. Typical thresholds sit around 1.5–2.0; values near 1 are the definition of normal.
  2. Why is reachability distance floored at the neighbour's k-distance rather than just using the raw distance?
    To stabilise the density estimate. If A happens to sit almost on top of B, the raw distance is nearly 0 and 1/mean would explode. Flooring at k-dist(B) means very close pairs are treated as being at B's characteristic scale, which stops a single coincidence dominating.
  3. One cluster is tight and another is loose. A point sits just outside the tight one. Would a global distance threshold catch it? Would LOF?
    A global threshold would miss it — its distance to its neighbours is smaller than ordinary distances inside the loose cluster, so any threshold that flags it would flood you with false alarms from the loose cluster. LOF catches it, because it compares the point only against its own neighbourhood.

4Isolation Forest

No distances at all. Count how many random cuts it takes to separate a point from the rest, and normalise.

Normaliser and score
c(n) = 2H(n − 1) − 2(n−1)n,   s(x, n) = 2−E[h(x)]c(n)
H(i) ≈ ln i + 0.5772 is the harmonic number. c(n) normalises by the path length a random point would need.
The method — what to actually do
  1. Compute c(n) for your subsample size (256 is the usual default).
  2. Use H(n−1) ≈ ln(n−1) + 0.5772.
  3. Average the path length h(x) for the point across all trees.
  4. Score = 2−E[h] / c(n).
  5. Read it: near 1 isolated almost at once = anomaly; near 0.5 unremarkable; well below 0.5 = deep inside a dense region.
  6. Never quote the raw path length — a path of 8 is short for n = 10 000 and long for n = 100.
Worked example — turning path lengths into scores
A forest built on subsamples of n = 256. One point is isolated after an average of 2 splits; another needs 12.
  1. Harmonic numberH(255) ≈ ln 255 + 0.5772 = 5.5413 + 0.5772 = 6.1185
  2. Normaliserc(256) = 2(6.1185) − 2 × 255256 = 12.2370 − 1.9922 = 10.2448
  3. Score for the quickly isolated points = 2−210.2448 = 2−0.1952 = 0.8734
  4. Score for the crowded points = 2−1210.2448 = 2−1.1713 = 0.4440
  5. Two more for the scaleE[h] = 4 → 0.763; E[h] = 8 → 0.582
  6. Interpret0.873 is a clear anomaly; 0.444 is more typical than average — it sits deep in a dense region
0.873 versus 0.444, from nothing but a count of random cuts. No distance was ever computed, which is why Isolation Forest is linear in n, trivially parallel, and the usual first thing to try on a large unlabelled dataset.
Practice
  1. Compute c(n) for n = 100.
    H(99) ≈ ln 99 + 0.5772 = 4.5951 + 0.5772 = 5.1723. c(100) = 2(5.1723) − 2(99)/100 = 10.3446 − 1.98 = 8.3646.
  2. With c(n) = 8.36, a point has average path length 3. What is its score?
    s = 2−3/8.36 = 2−0.3589 = 0.7797 — comfortably above 0.5, so anomalous.
  3. Why does Isolation Forest cope with high dimensions better than LOF?
    Because it never computes a distance. LOF depends entirely on nearest-neighbour distances, which concentrate in high dimensions until they carry no information. Isolation Forest only ever asks “does this point fall left or right of a random cut on a random feature?”, which stays meaningful.
