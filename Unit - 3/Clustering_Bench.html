The same points, the same cut, four different rules for the distance between two clusters. Single linkage takes the closest pair, so a thin bridge of points chains two groups together; complete takes the furthest pair and so insists on compactness; average sits between them; Ward merges whichever pair adds least to the total within-cluster spread.

The tree is drawn as it is built. The height of a join is the distance at which those two branches came together, so a tall join means two unlike groups. The dashed line marks where the algorithm currently stands; once the tree is complete you can drag it to re-cut.

Every point's distance to its MinPts-th nearest neighbour, sorted from largest to smallest. The knee of this curve is the usual way to choose eps: above the line the neighbourhood is too sparse to be dense, below it the point has enough company.

Implementation

read straight off the running functions
Distances are Euclidean throughout. Silhouette and Davies–Bouldin are undefined for a single cluster and for a cluster of one point, and are reported as “n/a” rather than a misleading number; for DBSCAN they are computed over the clustered points only, with noise excluded. Agglomerative linkage uses the Lance–Williams update, so Ward works in squared space and merge heights are square-rooted. DIANA advances in two phases — seed, then one defection per step. DBSCAN grows one cluster at a time, one wave of neighbours per step, and eps is set as a percentage of the data's diagonal so it stays meaningful when the axes are standardised. The code panel prints the live functions, so what you read is what just ran. Built for INT396 Unsupervised Learning, Units 2 and 3.
