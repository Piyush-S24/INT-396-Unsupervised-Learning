1The curse of dimensionality

The reason this unit exists: in high dimensions, distance stops discriminating and every method built on it degrades.

How fast the space empties
points per axis = N1/d,   samples for c per axis = cd
Coverage of the space falls exponentially with dimension. This is arithmetic, not a modelling choice.
The method — what to actually do
  1. To find how many samples give c points per axis in d dimensions: compute cd.
  2. To find the coverage you actually have from N samples: compute N1/d.
  3. To show distances concentrating: compute the mean and standard deviation of all pairwise distances, then the ratio sd/mean.
  4. As d rises that ratio falls toward 0 — every pair ends up the same distance apart.
  5. Practical reading: once sd/mean drops below about 0.1, nearest-neighbour methods are no longer carrying useful information.
Worked example — how fast the space empties
You want 10 sample points along each axis so that every region is reasonably covered.
  1. In 1 dimension101 = 10 samples
  2. In 2 dimensions102 = 100
  3. In 5 dimensions105 = 100 000
  4. In 10 dimensions1010 = 10 billion — more than you will ever have
  5. Turn it around: you have 1000 samples. Coverage per axis?10001/d
  6. Evaluated = 3 → 10001/3 = 10.0;  d = 10 → 2.0;  d = 20 → 1.4
  7. And the distance ratio, measured on 200 uniform random pointsd = 2 → sd/mean = 0.478; d = 10 → 0.189; d = 100 → 0.057
At d = 20, a thousand samples give barely one point per axis. And by d = 100 the spread of distances is under 6% of their mean — every pair is effectively equidistant, so “nearest neighbour” has stopped meaning anything.
Practice
  1. How many samples give 5 points per axis in 8 dimensions?
    58 = 390 625. In 12 dimensions it would be 512 ≈ 244 million — the exponent is what kills you, not the base.
  2. You have 10 000 samples in 6 dimensions. What coverage per axis?
    100001/6 = 104/6 ≈ 4.64 points per axis. Fewer than 5 divisions along each dimension — already quite sparse.
  3. Pairwise distances have mean 8.0 and standard deviation 0.3. What does that tell you?
    sd/mean = 0.3/8.0 = 0.0375, which is very low. The distances are tightly concentrated, so the nearest and farthest points are almost equally far away. Reduce dimensions before clustering — k-Means or DBSCAN on this data would be close to arbitrary.

2PCA, end to end

Centre, build the covariance matrix, take its eigenvectors, project. The eigenvalue is the variance along its own eigenvector.

Eigenvalues of a 2×2 covariance
Cu = λu,   det(C − λI) = 0 → λ2 − (tr C)λ + det C = 0
For a 2×2 matrix this is a quadratic you can solve by hand. The larger root is λ1.
The method — what to actually do
  1. Standardise if the features are in different units; otherwise just centre.
  2. Subtract the column means.
  3. Build C: var(x) and var(y) on the diagonal, cov off it. Divide every sum by n − 1.
  4. Write trace = var(x) + var(y) and det = var(x)var(y) − cov2.
  5. Solve λ2 − (trace)λ + det = 0.
  6. For each λ: substitute into (C − λI)u = 0, get a ratio, then normalise so ‖u‖ = 1.
  7. Explained variance = λ1 / (λ1 + λ2).
  8. Project: coordinate = centred point · u.
Worked example — the full computation on five points
Points (1,1) (2,3) (3,2) (4,5) (5,4). Both features share a scale, so centring alone is enough.
  1. Means and centringx̄ = (3, 3) → (−2,−2) (−1,0) (0,−1) (1,2) (2,1)
  2. Variances, dividing by 4var(x) = 4+1+0+1+44 = 2.5; var(y) = 4+0+1+4+14 = 2.5
  3. Covariance4 + 0 + 0 + 2 + 24 = 84 = 2.0
  4. Trace and determinanttr = 5.0;  det = (2.5)(2.5) − 22 = 6.25 − 4 = 2.25
  5. Solve the quadraticλ = 5 ± √25 − 92 = 5 ± 42 → 4.5 and 0.5
  6. First eigenvector(2.5 − 4.5)u1 + 2u2 = 0 → −2u1 + 2u2 = 0 → u1 = u2
  7. Normaliseu = (1√2, 1√2) = (0.7071, 0.7071), the 45° direction
  8. Explained variance4.55.0 = 90%
  9. Project all five points onto PC1−2.828, −0.707, −0.707, +2.121, +2.121
  10. Reconstruction error from PC1 alonetotal = (n−1)λ2 = 4(0.5) = 2.0
λ1 = 4.5 (90%), λ2 = 0.5 (10%), reconstruction error 2.0. The discarded eigenvalue is the error you will incur — known before you throw anything away.
Practice
  1. C has var(x) = 4, var(y) = 4, cov = 3. Find the eigenvalues and the explained variance of PC1.
    tr = 8, det = 16 − 9 = 7 → λ2 − 8λ + 7 = 0 → λ = 7 and 1. PC1 explains 7/8 = 87.5%.
  2. Eigenvalues are 5.0, 3.0, 1.5, 0.4, 0.1. How many components for 95%?
    Total = 10.0. Cumulative: 5.0 (50%), 8.0 (80%), 9.5 (95%). 3 components reach exactly 95%. Note the elbow is also after the third.
  3. If cov(x, y) = 0 and the variances are 9 and 4, what are the principal components?
    The matrix is already diagonal, so the eigenvalues are just the variances: 9 and 4, with eigenvectors (1,0) and (0,1). The original axes are the principal components — uncorrelated features leave PCA nothing to rotate.

3t-SNE neighbour probabilities

t-SNE turns distances into probabilities, which is why it preserves neighbourhoods and nothing else.

Neighbour probability
pj|i = exp(−d2(i, j)2σ2) ∑k≠i exp(−d2(i, k)2σ2)
A Gaussian centred on point i, then normalised so the row sums to 1. The Gaussian decays so fast that distant points contribute essentially nothing.
The method — what to actually do
  1. Compute the squared distance from i to every other point.
  2. For each, evaluate exp(−d2 / 2σ2) — these are unnormalised weights.
  3. Sum all the weights.
  4. Divide each weight by the sum. The results are the probabilities and they add to 1.
  5. Note how fast they decay: doubling the distance quarters the exponent's numerator and the weight collapses.
  6. In the real algorithm σ is tuned per point so each has roughly perplexity many effective neighbours.
Worked example — one row of the probability matrix
Four points on a line: A at 0.0, B at 0.5, C at 1.5, D at 4.0. Compute pj|A with σ = 1.
  1. Squared distances from Ad2(A,B) = 0.25; d2(A,C) = 2.25; d2(A,D) = 16.00
  2. Weight for Bexp(−0.252) = exp(−0.125) = 0.8825
  3. Weight for Cexp(−2.252) = exp(−1.125) = 0.3247
  4. Weight for Dexp(−16.002) = exp(−8) = 0.0003
  5. Sum0.8825 + 0.3247 + 0.0003 = 1.2075
  6. NormaliseB = 0.88251.2075 = 0.731; C = 0.269; D = 0.0003
  7. Compare D with CD is only 2.7× further than C, but its probability is 900× smaller
That decay is the whole reason t-SNE preserves neighbourhoods and nothing else. Anything beyond the local Gaussian contributes nothing to the objective, so the optimisation has no incentive to place distant clusters correctly relative to one another — which is why you must never read distances off a t-SNE plot.
Practice
  1. With σ = 1, compute the unnormalised weight for a point at distance 2.
    exp(−2²/2) = exp(−2) = 0.1353. At distance 3 it would be exp(−4.5) = 0.0111 — a 50% increase in distance cuts the weight by more than 12×.
  2. Why does each point get its own σ rather than one global value?
    Because density varies across the data. A point in a dense region needs a small σ to have a meaningful neighbourhood; one in a sparse region needs a large one. Tuning σ per point so each has the same perplexity makes dense and sparse regions comparable.
  3. A t-SNE plot shows cluster A twice the diameter of cluster B, and the two sit far apart. What can you conclude?
    Nothing about either. t-SNE expands sparse regions and compresses dense ones, so relative size is an artefact. Distances between clusters are essentially arbitrary. The only safe reading is which points are neighbours of which.

4Autoencoder arithmetic

The bottleneck is a compression ratio, and that ratio is what forces the network to learn something rather than copy.

Compression and loss
compression = input dimensionscode dimensions,   loss = ‖x − ̂x‖2
A linear autoencoder with squared-error loss learns exactly the subspace PCA finds. Everything extra comes from the non-linear activations.
The method — what to actually do
  1. Count the input dimensions (for an image, height × width × channels).
  2. Divide by the code size to get the compression ratio.
  3. Express the kept fraction as code / input, as a percentage.
  4. Check the bottleneck is genuinely narrower than the input — if not, the network can learn the identity map and nothing is forced.
  5. For anomaly detection: train on normal data only, then flag inputs with high reconstruction error.
  6. Compare against PCA: if your data is nearly linear, PCA gives the same subspace with no training and an exact answer.
Worked example — sizing a bottleneck, and the trap
An autoencoder on 28×28 greyscale digit images with a 32-unit code.
  1. Input dimensions28 × 28 = 784 numbers per image
  2. Compression ratio78432 = 24.5×
  3. Fraction kept32784 = 4.08% → 95.9% of the dimensions are discarded
  4. So what must those 32 numbers encode?not pixels — there is no room. They must capture slant, stroke thickness, loop size, digit identity: the factors that actually vary
  5. Now widen the bottleneck to 784compression ratio = 784784 = 1× → the network can copy input straight to output
  6. What the loss does thenreconstruction error → 0, and nothing has been learned — it is an identity function wearing a neural network
  7. The diagnostica near-perfect reconstruction is a reason to be suspicious, not pleased
24.5× compression, 95.9% of dimensions discarded. The constraint is the teacher: with 32 units the network must decide what matters; with 784 it never has to decide anything.
Practice
  1. A 64×64 RGB image goes through a 128-unit bottleneck. What is the compression ratio?
    Input = 64 × 64 × 3 = 12 288. Ratio = 12288/128 = 96×, keeping about 1.04% of the dimensions.
  2. Your autoencoder reaches near-zero reconstruction error on the training set. Is this good news?
    Probably not. Either the bottleneck is too wide and it has learned the identity map, or it has memorised the training set. Check the error on held-out data; if that is also near zero and the bottleneck is genuinely narrow, then it is real. Otherwise narrow the bottleneck.
  3. When would you use PCA instead of an autoencoder?
    When the data is roughly linear, when you need the result to be deterministic and reproducible, when you want an explicit variance-explained figure, or when you have too little data to train a network. PCA needs no training, runs in seconds and gives the same answer every time.
